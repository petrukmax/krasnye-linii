# Статическая версия для GitHub Pages

В проекте есть два независимых варианта сайта:

1. **Основное приложение** — React + TanStack Start, запускается через `npm run dev`.
2. **Статическая версия** — обычные HTML/CSS-файлы в корне проекта, предназначенные для GitHub Pages.

Статическая версия повторяет оформление основного сайта: тёмный архивный фон, золотистые линии, serif-заголовки, широкие буквенные интервалы в навигации, карточки материалов, хронологические списки и страницы первоисточников.

---

## 1. Что лежит в корне проекта

```text
index.html                         ← главная страница (обязательно в корне)
404.html                           ← страница ошибки для GitHub Pages
manifest.webmanifest               ← PWA-манифест
robots.txt
.nojekyll                          ← отключает обработку Jekyll на GitHub Pages

pages/
  blok-i.html                      ← блок I основного архива
  blok-ii.html
  blok-iii.html
  blok-iv.html
  material/
    <slug>.html                    ← 13 страниц материалов основного архива
  mezhdunarodnyj-vzglyad/
    index.html                     ← главная раздела «Международный взгляд»
    blok-i.html … blok-iv.html
    material/
      <slug>.html                  ← 20 страниц материалов раздела
  novosti/
    index.html                     ← главная раздела «Новости»
    2025.html                      ← материалы 2025 года
    2026.html                      ← материалы 2026 года
    material/
      <slug>.html                  ← страницы материалов раздела

static/
  site.css                         ← сгенерированная копия стилей
  hero-archive.jpg
  hero-international.jpg
  hero-news.jpg
  favicon.png
  icon-512.png

scripts/
  build-static-site.mjs            ← генератор статических страниц
  check-static-links.mjs           ← проверка внутренних ссылок

    site.css                       ← ИСХОДНЫЙ CSS статической версии
```

`index.html`, `404.html`, `pages/`, `static/site.css`, `manifest.webmanifest` и `robots.txt` — **сгенерированные файлы**. Их не нужно править вручную: при следующем запуске генератора изменения будут перезаписаны.

---

## 2. Как это работает

Генератор `scripts/build-static-site.mjs`:

1. Загружает данные из тех же TypeScript-файлов, что и основное приложение:
   - `src/data/archive.ts` — основной архив;
   - `src/data/international.ts` — раздел «Международный взгляд»;
   - `src/data/news.ts` — раздел «Новости».
2. Рендерит HTML-строки по шаблонам внутри генератора.
3. Копирует стили и изображения в `static/`.
4. Создаёт главную, страницы блоков, страницы материалов, 404 и служебные файлы.
5. Все внутренние ссылки делает **относительными** — поэтому сайт работает и по адресу `https://user.github.io/repo/`, и локально.

Запуск:

```bash
npm install        # один раз
npm run build:static
```

После генерации полезно проверить ссылки:

```bash
npm run check:static
```

Если всё в порядке, команда выведет:

```text
Внутренние ссылки в порядке.
```

## 3. Как обновлять контент

### 3.1. Изменение существующего материала

Контент берётся из файлов данных.

Для основного архива:

```text
src/data/archive.ts
```

Для раздела «Международный взгляд»:

```text
src/data/international.ts
```

Для раздела «Новости»:

```text
src/data/news.ts
```

Можно менять заголовки, авторов, даты, аннотации, тезисы, ссылки на первоисточники. После изменений:

```bash
npm run build:static
npm run check:static
```

Затем закоммитить и запушить изменения.

### 3.2. Добавление нового материала

1. Откройте нужный файл данных.
2. Добавьте объект в массив `materials` или `internationalMaterials`.
3. Укажите уникальный `slug` — из него будет создано имя страницы:
   `pages/material/<slug>.html`,
   `pages/mezhdunarodnyj-vzglyad/material/<slug>.html` или
   `pages/novosti/material/<slug>.html`.
4. Убедитесь, что `blockId` совпадает с одним из существующих блоков (`i`, `ii`, `iii`, `iv`),
   а для раздела «Новости» поле `year` — с одним из годов (`2025` или `2026`).
5. Запустите `npm run build:static`.

Генератор сам:

- создаст страницу материала;
- добавит материал в список соответствующего блока;
- обновит блок «Новые поступления» на главной, если материал попадает в последние по дате;
- обновит счётчики материалов;
- создаст ссылки «предыдущий / следующий» внутри блока.

Старые `slug` лучше не менять: по ним уже могут быть внешние ссылки. Если переименование необходимо, старый URL начнёт отдавать 404.

### 3.3. Добавление нового блока

Для основного архива:

1. В `src/data/archive.ts` расширьте тип:
   ```ts
   export type BlockId = "i" | "ii" | "iii" | "iv" | "v";
   ```
2. Добавьте объект в массив `blocks`.
3. Запустите `npm run build:static`.

Для раздела «Международный взгляд» — аналогично в `src/data/international.ts`:
`InternationalBlockId` и `internationalBlocks`.

Для раздела «Новости» новый год добавляется в `src/data/news.ts`:
тип `NewsYear`, массив `newsBlocks` и значения поля `year` у материалов.

Генератор автоматически создаст новую страницу блока и добавит пункт в навигацию.

### 3.4. Изменение текстов главной страницы

Тексты hero-блока, концепции раздела и блока «Главная идея» находятся не в данных, а в шаблонах генератора:

- главная: функция `renderHome()`;
- главная раздела «Международный взгляд»: функция `renderInternationalHome()`;
- главная раздела «Новости»: функция `renderNewsHome()`;
- шапка и подвал: `renderHeader()` и `renderFooter()`.

После правок:

```bash
npm run build:static
```

## 4. Как менять оформление статической версии

Оформление статической версии не собирается из React-компонентов. Оно живёт отдельно:

- **CSS:** `scripts/static-site/site.css`;
- **HTML-шаблоны:** `scripts/build-static-site.mjs`.

После правки CSS или шаблонов:

```bash
npm run build:static
```

> Важно: `static/site.css` — это копия. Редактируйте `scripts/static-site/site.css`, иначе изменения исчезнут при следующей генерации.

### Если вы поменяли дизайн основного приложения

Основное приложение и статическая версия — разные реализации. Изменения в `src/routes/*.tsx` или `src/styles.css` **не попадут** в статические страницы автоматически.

Порядок действий:

1. Посмотрите, что изменилось в React-версии: цвета, отступы, сетка, состав блоков.
2. Перенесите изменения в `scripts/static-site/site.css`.
3. Если изменилась разметка — поправьте соответствующий `render*` в `scripts/build-static-site.mjs`.
4. Запустите `npm run build:static`.
5. Проверьте `npm run check:static`.

## 5. Публикация на GitHub Pages

Сборка на GitHub не требуется: готовые HTML-файлы уже лежат в репозитории.

1. Загрузите проект в GitHub (ветка `main`).
2. Откройте репозиторий → **Settings** → **Pages**.
3. В разделе **Build and deployment**:
   - **Source:** `Deploy from a branch`;
   - **Branch:** `main`;
   - **Folder:** `/(root)`.
4. Нажмите **Save**.
5. Подождите 1–3 минуты. Сайт откроется по адресу:
   - `https://<username>.github.io/<repo>/` — обычный репозиторий;
   - `https://<username>.github.io/` — если репозиторий называется `<username>.github.io`.

Файл `.nojekyll` уже создан, поэтому GitHub Pages не будет пытаться обрабатывать сайт через Jekyll.

### Обновление сайта

После изменений:

```bash
npm run build:static
npm run check:static
git add index.html 404.html pages static manifest.webmanifest robots.txt .nojekyll
git commit -m "Обновление статической версии"
git push
```

GitHub Pages подхватит новый коммит автоматически.

## 6. Локальная проверка

Не открывайте страницы через `file://` — лучше запустить простой HTTP-сервер из корня проекта:

```bash
# вариант 1
npx serve .

# вариант 2 (если установлен Python)
python -m http.server 8000
```

Затем откройте:

```text
http://localhost:8000/
```

Проверьте:

- главную;
- переходы по блокам I–IV;
- раздел «Международный взгляд»;
- несколько страниц материалов;
- мобильную ширину;
- прямые ссылки на вложенные страницы.

## 7. Важные технические ограничения

### Не переименовывайте `static/` в `assets/`

В корне проекта уже есть служебная папка `assets/` у Nitro. Если положить туда статические стили, обычная сборка приложения (`npm run build`) начнёт воспринимать их как серверные ассеты и упадёт на обработке CSS. Поэтому статическая версия использует папку `static/`.

### Не удаляйте `nitro: { renderer: false }` из `vite.config.ts`

В корне лежит собственный `index.html`. Без этой настройки Nitro автоматически определяет его как renderer-шаблон и пытается обрабатывать статическую версию во время сборки React-приложения. Настройка отключает это поведение.

```ts
nitro: { renderer: false } as never,
```

### Ссылки должны оставаться относительными

Не добавляйте ссылки вида `/pages/blok-i.html`. На GitHub Pages проект обычно открывается не из корня домена, а из подпапки `/repo/`, поэтому ссылка от корня сломается.

Правильно:

```html
<a href="pages/blok-i.html">Блок I</a>
<a href="../../index.html">Главная</a>
```

Неправильно:

```html
<a href="/pages/blok-i.html">Блок I</a>
```

`npm run check:static` проверяет и битые ссылки, и ссылки от корня сайта.

### Не редактируйте сгенерированные файлы вручную

Не правьте:

- `index.html`;
- `404.html`;
- `pages/**`;
- `static/site.css`;
- `manifest.webmanifest`;
- `robots.txt`.

Все эти файлы перезаписываются генератором. Исключение — срочная правка, после которой всё равно нужно обновить исходники и пересобрать сайт.

## 8. Краткий чек-лист при любом изменении

1. Изменили контент → правьте `src/data/archive.ts`, `src/data/international.ts` или `src/data/news.ts`.
2. Изменили текст главной или разметку → правьте `scripts/build-static-site.mjs`.
3. Изменили оформление → правьте `scripts/static-site/site.css`.
4. Запустите:
   ```bash
   npm run build:static
   npm run check:static
   ```
5. Проверьте сайт локально через HTTP-сервер.
6. Закоммитьте и запушьте изменения.
7. Дождитесь обновления GitHub Pages.

## 9. Быстрая диагностика

| Проблема | Что проверить |
| --- | --- |
| На GitHub Pages открывается README или пустая страница | В настройках Pages выбрана ветка `main` и папка `/(root)`, `index.html` лежит в корне. |
| Вложенная страница отдаёт 404 | Ссылка должна быть относительной; файл должен существовать в `pages/`. Запустите `npm run check:static`. |
| Пропали стили | В `static/site.css` есть файл, папка `static/` закоммичена. |
| Не загрузились изображения | Проверьте `static/hero-archive.jpg` и `static/hero-international.jpg`. |
| Шрифты выглядят иначе | Google Fonts может быть недоступен; сработали системные fallback-шрифты. |
| Старая версия сайта | Обновите страницу с очисткой кеша и подождите завершения деплоя GitHub Pages. |
| `npm run build` падает на CSS | Проверьте, что статические файлы лежат в `static/`, а не в корневой `assets/`, и что в `vite.config.ts` осталось `nitro: { renderer: false }`. |
| Генератор не запускается | Выполните `npm install`, проверьте Node.js 20+ и наличие папки `scripts/static-site/`. |
